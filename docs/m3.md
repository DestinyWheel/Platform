# M3 实现说明：回放 / 聊天 / 观战 / 战绩 + Elo

M0–M2 解决的是"能不能玩、能不能热插拔"。M3 补的是**一局结束之后**的部分：你想复盘、想吹两句、想知道自己排第几。

## 一、回放

动作日志从 M1 就在写了，M3 只是把它变成能看的东西。

服务端把日志从头重放一遍，每一步留一张快照：

```
start 记录里的 { seed, players, options }
        ↓ createInitialState
        ↓ applyAction（逐条）
   [{ seq, view }, { seq, view }, ...]
```

前端只负责在时间轴上切（上一步/下一步/播放/拖动）。之所以敢把整份快照发给客户端，是因为**每张快照都是观战者视角**——回放里同样看不到别人的手牌，也不会带出 `rngSeed`。

代价是 payload 会随步数增长，所以有 400 步上限（`truncated` 标记）。真遇到长局，再改成"客户端拉日志 + 服务端只给初始态"。

### 顺手修的一个真 bug

M1 的超时记录写的是 `action: null`——因为 `applyTimeout` 内部决定了动作但没往外传。结果就是**任何发生过超时的局都无法完整回放**，日志会在那一步断掉。

M3 把 `applyTimeout` 的返回值改成 `{ state, effects, action, actor }`，超时也照实入库。冒烟里专门验了：超时桌的回放里能看到 `kind === 'timeout'` 的那一步。

## 二、聊天

- 存库（`table_chat`），不是内存——重启后聊天记录还在
- 通过已有的 WS 发（`{ t: 'chat', tableId, text }`），服务端校验长度（≤200 字）后落库并广播
- 客户端不额外维护聊天状态，直接读快照里的最近 30 条

把聊天塞进快照而不是单独的消息类型，是为了少一条同步路径：状态变了就整份刷新，永远不会出现"日志更新了但聊天没更新"这种错位。

## 三、观战人数

`Presence` 是一个很薄的接口：

```ts
presence.join(tableId, connectionId, userId)
presence.leave(tableId, connectionId)
presence.viewers(tableId)   // 按 userId 去重
```

单实例用 Map，多实例换 Redis 就行——和 `Bus`、`TimerScheduler` 是同一个套路。同一个人开三个标签页只算一个人。

## 四、战绩 + Elo

### 战绩

一局结束时写 `match_results`（`ON CONFLICT DO NOTHING`，天然幂等）。排行榜和"我的战绩"都从这张表算，不扫描 `tables`。

写入时机很关键：**在 CAS 成功之后**。如果先算分再写库，CAS 失败会导致分数算了一遍却没落库；现在的顺序保证"只有当这次状态推进真的赢了，才算这局结束"。

### Elo

多人局版本，规则很简单：

- 两两算期望胜率 `E = 1/(1+10^((R_对手 - R_自己)/400))`
- 实际得分：赢 1、平 0.5、输 0
- 求和后除以 `(n-1)`，这样一局的最大变动不随人数膨胀
- K 因子按场次递减：`<10 场 40`、`<30 场 28`、之后 `20`

结果是**零和**的：2 人 1500 分局，赢家 +20、输家 −20，总分仍是 3000。冒烟里直接断言了这个守恒关系。

几个约定：

- 每人每个游戏独立评分，默认 1500
- 房主把开桌选项 `ranked` 设成 `false` 就是休闲局，不计分
- 人机（`bot`）不参与评分

## 验证

`pnpm smoke` 现在五段：

```
▶ 阶段一  自动发布 → 开桌 → 打两步
▶ 阶段二  上传 0.2.0（不重启）→ 老桌锁旧版 / 新桌新版 / 非管理员 403
▶ 阶段三  重启恢复 → 日志重放哈希一致
▶ 阶段四  聊天广播 / 2 人在看 / 战绩 1 场 / Elo 总分守恒 / 回放 7 步
▶ 阶段五  超时代打 → 超时动作可回放
```

## 已知边界

| 项 | 现状 | 后续 |
|---|---|---|
| 回放 payload | 全量快照，400 步上限 | 长局改成拉日志客户端重放，或分页 |
| 聊天 | 无敏感词、无频率限制 | 私人平台暂不需要；要开放就先加限流 |
| 在线人数 | 进程内 Map | 多实例换 Redis |
| Elo | 只按最终名次，不看中途表现 | 够用；要更准可换 Glicko-2 |
| 观战 | 能看、有人数，但没有"观战者列表" | 加个名单不难，等有人要求再说 |
