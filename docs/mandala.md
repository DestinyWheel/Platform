# 曼荼罗（Mandala）插件

规则来源：`D:\Workspace\gamer\Mandala\gdd.md` + `scripts/game_core.lua`（856 行的完整实现）。

**以 Lua 实现为准**——gdd.md 是摘要，Lua 才是自洽的。三处不一致已在实现前确认：

| 点 | gdd.md | 实际采用 |
|---|---|---|
| 打原野 | "不限制打出的卡牌数" | 一次一张，但同一回合可以连续出（等价） |
| 结算取什么 | 听起来含原野 | **只取高山**，原野牌不参与分配，结算结束整幅清空 |
| 结算后谁先动 | 未写 | **换人** |
| 结算先手平局 | 未写 | **触发结算的人先选** |
| 结算收尾 | 未写 | 轮到高山空为止，**另一幅曼荼罗不受影响** |

## 规则要点

- 牌堆 48 张（6 色 × 8），牌面只有颜色，没有数字
- 起始：每人 6 张手牌 + 2 张沙杯（盖着）；每人抽 2 张，第 *i* 张进第 *i* 幅曼荼罗的高山
- 三种行动：打高山（1 张，补抽至多 3 张，手牌上限 8，**结束回合**）；打原野（1 张，不结束回合）；弃 N 补 N（结束回合）
- 颜色规则：同一幅曼荼罗里，一种颜色只能出现在一个区域（原野A / 高山 / 原野B）
- 触发：某幅曼荼罗集齐 6 色
- 结算：原野牌多者先选（平局由触发者先选），轮流从**高山**拿走一种颜色的全部牌
  - 该色已在长河 → 全部进沙杯
  - 不在 → 1 张进最小空格、其余进沙杯；长河满则全进沙杯
- 结束：有人长河集齐 6 色（立即结束），或牌堆抽空后再完成一次结算
- 计分：长河第 *i* 格的倍率是 *i*，乘上沙杯里该颜色的张数

## 实现结构

```
playing   ──触发结算──▶ settling ──高山空──▶ playing（换人）
   │                        │
   └──长河满 / 牌堆空──────────────────▶ finished
```

状态里只有一份数据：`deck/drawPos`、`hands`、`river[6]`、`cups`、`mandalas[{fields[2], mountain}]`、`settlement`。

结算不是一个"子游戏状态"，而是 `settlement = { mandalaIdx, picker }` + 一个 `settling` 阶段，`picker` 跟着 `turn` 走——这样「谁在行动」只有一处真相。

| 沙杯 | 完整（颜色和张数） | 仅张数 | 仅张数 |
| 长河 | 完整 | 完整 | 完整 |
| 曼荼罗 | 完整 | 完整 | 完整 |
| 牌堆 | 剩余张数 | 剩余张数 | 剩余张数 |

自己的沙杯一直可见。规则书原文：

> You may look at the cards in your hand and Cup at any time but keep them hidden from your opponent.

所以沙杯只是**对对手**盖着：对手只给张数，对局结束后对所有人翻开。冒烟里断言了「观战者的 view 里既没有 `you` 也没有 `opponent`」。

## 顺带扩展了插件契约

之前 `legalActions` 只给动作类型（`['roll']`），对曼荼罗不够用——UI 需要知道「第 3 张手牌能不能打到第 2 幅曼荼罗的高山」。

所以加了 `GamePlugin.legalMoves(state, playerId): AnyAction[]`，返回带参数的具体动作，一路传到前端：

- `engine.enumerateLegalMoves()`：插件没实现就退回"只给类型"，老插件不受影响
- `TableSnapshot.legalMoves` / `ClientSnapshot.legalMoves`
- 发布流水线的随机漫步也改用它——现在能对"动作必须带参数"的游戏做冒烟
- 将来的简单人机也直接吃这个接口

## 回合内撤销与不限时房间

两条**规则变体**，由开桌选项控制：

### 撤销

`undo` 动作，只在自己的回合内有效。实现方式是**状态内快照栈**：

```
每个改局面的动作（打高山 / 打原野 / 弃牌）先 push 一份当前状态的 JSON（不含 undo 自己）
undo 时 pop 出来 Object.assign 回去
```

- 快照栈上限 20
- **换手、进入结算都会清空**——所以不可能撤到别人的回合去
- 撤销本身不 push 快照，连按两次会一直往前退（符合直觉）

为什么不放在平台层做：撤销是否安全取决于规则（有些游戏一旦揭示隐藏信息就不能悔）。所以它是插件的能力，不是宿主的。

### 不限时房间

开桌时 `options: { untimed: true, turnMs: 0 }`：

| | 限时房间 | 不限时房间 |
|---|---|---|
| 截止时间 | 30 秒（可配） | **没有**，超时托管不会触发 |
| 打高山后 | 自动换手 | **不换手**，可以继续出牌 |
| 弃牌后 | 自动换手 | **不换手** |
| 结束回合 | 随时可点 | 只能主动点 |

这类房间才配得上"悔棋"——因为整个回合都在你手上，撤销才有意义。

实现上只有两处：`refreshDeadline` 遇到 `turnMs === 0` 直接返回 `null`；插件在 `state.untimed` 为真时不调 `swapTurn`。

## 美术：不用一张图

官方美术是 Lookout Games 的版权作品（插画 + 平面设计：atelier198 / Klemens Franz），不能拿。
但曼荼罗这个符号本身是古印度的，**图案属于公共领域**——所以这里不找素材，直接画：

- **三环 = 三个区域**：圆心是我的原野，中环是高山，外环是对方原野。离你越远越靠外，不用记。
- **六个 60° 扇区 = 六种颜色**。"一色只能在一个区域"这条规则因此变成视觉事实：某个颜色的
  砂只会出现在它所在的那一环里。
- **彩砂是算出来的**：每个颜色一张 12×12 的 SVG `<pattern>`，颗粒坐标由固定种子生成
  （白点提亮、黑点压暗）。比 `feTurbulence` 便宜得多，而且每次渲染完全一致。
- **结算时砂会散开**：拿空的那一格用一个"幽灵"元素播 750ms 的缩放+淡出动画。
  这是实体桌游做不到的部分，也是数字版唯一值得加的东西。

## 已知边界

| 项 | 说明 |
|---|---|
| 撤销范围 | 只在当前回合内；结算开始后不可退（结算已经分牌了） |
| 撤销与 bot | 机器人不会使用撤销（`legalMoves` 不包含它，避免来回悔棋死循环） |
| 长河满即结束 | 立刻结束，不结算剩余的曼荼罗——和参考实现一致 |
| 版本号 | 加了规则变体但仍标 `0.1.0`。开发态靠 `allowReplace` 覆盖；正式发布请升版本号 |
