# M4 实现说明：人机

目标不是"做个强 AI"，而是**让单人也能开局**，并且证明机器人走的是和真人完全相同的通道。

## 原则：bot 就是一个没有 socket 的玩家

宿主里没有 `if (isBot)`。机器人提交的动作和真人一样经过：

```
act() → validate() → reduce() → CAS 写库 → 广播
```

唯一的区别是：提交者不是一条 WebSocket 连接，而是一个定时器。

## 契约

```ts
interface BotPolicy {
  id: string;
  name: string;
  choose(ctx: BotContext): AnyAction | null;   // null = 交给平台兜底
}

interface BotContext {
  view: PublicView;      // 裁剪后的视图
  me: PlayerId;
  legal: AnyAction[];    // 来自 legalMoves，带参数
  level: 'easy' | 'normal' | 'hard';
  rng: () => number;
}
```

插件通过 `bots: BotPolicy[]` 导出策略。**没有策略的插件也能玩人机**——平台会从 `legalMoves` 里随机挑一个。

`BotContext` 里只有裁剪后的 `view`，没有完整 state。这是刻意的：以后加难度只能靠在可见信息上算得更好，而不是偷看对手手牌。

## 决策在 worker 里做

策略属于游戏知识，所以它在插件所在的线程里执行：

```
主线程                          worker
  │  botMove(state, level)   →    │  跑策略 / 兜底随机
  │  ←  { actor, action }         │
```

主线程拿到 `{ actor, action }` 后调用 `act()`，和真人提交完全相同。

**不盲信插件**：返回的动作必须在 `legalMoves` 里逐项比对（type + payload 深比较），不在就退化成随机。策略抛异常也走兜底。

## 调度

每次 CAS 写成功后检查：如果当前行动者是机器人，安排一个 400–1000ms 的定时器。

- 假装"思考"，避免对手看到瞬间连走三步
- `unref()`，关服时由 `stopBots()` 统一清理
- 同一张桌只会有一个待触发的定时器

## 补位

开桌时传 `options.bots: N`，**开局那一刻**才补座位：

```
人类玩家坐下 → 房主点开始 → 补 N 个机器人（不超过 maxPlayers）→ 校验人数是否 ≥ min
```

这样机器人不会占着座位导致别人加不进来。

## 计分

机器人局**不计战绩、不计 Elo**：`recordResult` 里要求「人类玩家 ≥ 2」，一人一机只有 1 个人类，自然跳过。

## 已实现的两个策略

| 游戏 | 策略 |
|---|---|
| 曼荼罗 | 贪心：结算时拿高山上张数最多的颜色；出牌时优先打"这幅曼荼罗还没出现过的颜色"来推进集齐六色 |
| 骰子 | 没有策略（只有唯一动作），走平台随机兜底 |

## 验证

```
▶ 阶段九：人机
✓ 单人开局补位成功：爱丽丝 vs 机器人 1
✓ 机器人自动走了一步：seq 2 → 3
✓ 机器人动作已入库（1 条，actor 形如 bot:…）
```

第三条是重点：机器人提交的动作**和真人一样写进了 `match_actions`**，所以回放、审计、重放校验对它同样成立。

## 已知边界

| 项 | 现状 |
|---|---|
| 难度分级 | `level` 已透传，但目前只区分 easy（随机）和其余（插件策略） |
| 策略数量 | 每个游戏只有一条策略，没有"简单/困难"两档可选 |
| 决策耗时 | 单步 5 秒超时（跟普通调用一样），超时会退化成随机 |
| 开局后加机器人 | 不支持，只能在开局时补位 |
